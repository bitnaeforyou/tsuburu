# 오프라인 열람·작가·다국어·의미 검색 팩 설계

작성일: 2026-09-09
선행 스펙: `2026-09-09-artifact-artifacts-design.md`

## 1. 왜 네 가지를 함께 하나

앞 스펙까지 오면 검색과 대사 검색은 되지만, 쓰다 보면 같은 자리에서 막힌다.
읽던 작품이 사라지거나 네트워크가 없으면 아무것도 못 보고(오프라인), 마음에
드는 그림을 그린 사람의 나머지를 보려면 이름을 다시 타이핑해야 하고(작가),
한국어가 아닌 제목은 검색이 이상하게 걸리고(다국어), 구절로 찾는 의미 검색은
"모델이 필요하다"며 비워 둔 채였다.

넷 다 저장소를 하나씩 건드리거나(다운로드·작가), 저장 포맷을
바꾸거나(다국어), 이미 있는 인덱스에 입구만 다는(팩) 일이라 같이 묶었다.

## 2. 다국어 매칭

매치 코드는 자모 하나를 `0x80..=0xC3` 한 바이트로, ASCII는 소문자로 접었다.
**나머지 문자는 전부 버렸다.** 일본어 제목은 구두점만 남아 아무 질의에나
걸렸고, 키릴·태국어도 마찬가지였다.

에스케이프를 하나 둔다.

```
ESCAPE(0xC4) + nibble(0xC5+h3) nibble(h2) nibble(h1) nibble(h0)
```

BMP 밖(`> 0xFFFF`)은 버린다 — 이모지는 검색어가 아니다. 소문자화는 넣기 전에
한다. 바이트 값이 자모 범위와 ASCII 어디와도 겹치지 않으므로 기존 스캐너·
n-gram 해시가 그대로 돌아간다. 한 문자가 5바이트라 6바이트 창(`N=6`)에
한 글자 남짓이 들어가는데, 라틴 아닌 문자가 이어지는 질의에서는 이게 오히려
창을 문자 경계에 맞춘다.

두 저장소를 다시 가져와야 한다(대사 스키마 5, 메타 스키마 4).

인식도 언어를 따른다. Vision에 스크립트를 전부 요구하면 정확도가 떨어지므로
`OcrOptions::for_language`가 hitomi의 언어 이름을 인식 태그로 옮기고
(`korean`→`ko-KR`, `chinese`→`zh-Hans`+`zh-Hant`, 모르는 이름→`en-US`),
그라인더는 언어 설정이 바뀔 때 엔진을 다시 만든다. 만드는 함수를 주입받으므로
인식이 없는 플랫폼에서는 아무 일도 일어나지 않는다.

## 3. 다운로드와 오프라인 열람

`downloads.redb` + `images/`. 이미지는 **hitomi가 이미 쥐여주는 해시로**
주소를 삼는다. 앞 두 글자로 갈라 담고, 파일명은 `<해시>.<avif|webp>`다.

- 같은 페이지를 쓰는 재업로드본이 여러 개여도 파일은 하나다.
- 작품을 지울 때는 **다른 작품이 안 쓰는 페이지만** 지운다.
- 부분 다운로드가 정상이다. 진행률은 `pages`/`have`로 낸다.
- 쓰기는 `.part`에 하고 마지막에 이름을 바꾼다. 중간에 죽어도 반쪽 파일이
  다음 실행에서 정상으로 보이지 않는다.

경로는 64자 hex와 확장자 두 가지만 통과시킨다. 해시가 URL에서 오므로
`../`가 섞일 자리를 아예 없앤다.

읽기 경로는 두 군데를 바꿨다.

- **이미지 프록시**: 디스크를 먼저 본다. 있으면 네트워크로 안 간다.
- **갤러리 조회**: hitomi가 실패하면 디스크에 있는 페이지 목록으로 응답을
  만든다. 제목·언어·페이지만 있고 태그는 비지만, 읽는 데는 그걸로 충분하다.
  받은 적 없는 작품은 원래의 네트워크 오류를 그대로 낸다.

작업은 배경에서 `JoinSet`으로 돌고 페이지 6개를 동시에 받는다. 상태는
메모리의 맵이라 서버를 껐다 켜면 사라지지만, 디스크에 있는 것은 남으므로
"나머지 받기"로 이어 받으면 된다.

## 4. 작가

스냅샷의 `artist:<이름>` 용어를 그대로 쓴다. 새 색인이 필요 없다.

- 언어별 개수는 `offset==0`일 때만 낸다. 첫 페이지에서 한 번 세고, 더 보기는
  ID만 받는다.
- 팔로우는 즐겨찾기·기록과 같은 저장소의 `artists` 테이블(이름 소문자 →
  추가 순번). 이미 팔로우한 이름을 다시 눌러도 순서가 바뀌지 않는다.
- 갤러리 화면의 작가 이름이 이 페이지로 간다.

스냅샷이 없으면 목록이 비고, 화면은 그것을 오류로 보이지 않게 다룬다.

## 5. 의미 검색 팩

인덱스에는 구절마다 벡터가 있다. 질의를 벡터로 바꾸는 쪽만 없다. 그 쪽은
4B 모델이고, 나머지를 쓰는 사람에게 강요할 크기가 아니다.

그래서 **선택이고 바깥에 둔다.** OpenAI 임베딩 API를 말하는 서버 주소와 모델
이름을 설정에 넣으면 구절 모드가 나타난다. 기본값은
`http://127.0.0.1:8080/v1/embeddings` / `Qwen3-Embedding-4B` / 1024차원.

- 차원이 더 길면 앞 1024개로 자르고 다시 정규화한다(MRL). 이 모델이 그렇게
  쓰도록 학습돼 있다.
- **틀린 모델이 제일 위험하다.** 그럴듯한 벡터가 오고 결과만 쓸모없어져서,
  코퍼스가 나쁜 것처럼 보인다. 그래서 확인 버튼을 둔다: 인덱스에 이미 있는
  구절을 다시 임베딩해 저장된 벡터와 코사인을 잰다. 0.9 미만이면 모델이
  다르다고 말한다.
- 서버가 안 떠 있으면 그렇게 말한다. 조용히 빈 결과를 주지 않는다.

실측 — artifact의 진짜 인덱스(2,537,826구절 / 108,369편)에 Qwen3-Embedding-4B
Q8_0을 llama.cpp로 띄워 붙였다. `manifest.json`이 모델·차원(1024)·정규화를
그대로 적어두고 있어, 앞서 파일에서 읽어낸 것과 맞는지도 확인됐다.

| | |
|---|---|
| 같은 모델로 재임베딩 → 저장된 벡터와 코사인 | **1.0001** (ok) |
| 다른 모델(무작위 단위 벡터) | 0.028 (틀렸다고 보고) |
| 문구 한 건 | 1.5 ~ 3.4초 (대부분 4B 모델이 질의를 임베딩하는 시간; 254만 벡터 훑기는 0.2초) |

1.0을 살짝 넘는 것은 저장된 벡터가 SQ8로 양자화돼 복원 노름이 정확히 1이
아니기 때문이다.

질의는 모두 결과의 낱말을 그대로 쓰지 않았다.

| 질의 | 1위 |
|---|---|
| 선생님과 제자가 방과 후 교실에서 단둘이 | "선생님.. 드디어 둘만 있게 됐네요.." (0.652) |
| 여동생이 오빠 방에 몰래 들어온다 | "유혹하는 여동생 장난감 놀이" (0.737) |
| 온천 여행에서 우연히 마주쳤다 | "저랑 온천 여행 가주세요" (0.700) |

## 6. 하지 않은 것

- 다운로드 큐의 영속화. 껐다 켜면 진행 중이던 작업은 잊고, 디스크에 있는
  것에서 이어 받는다.
- 작가 이름의 별칭·표기 흔들림 통합. 스냅샷의 이름을 그대로 쓴다.
- 모델 번들. 어떤 형태로도 넣지 않는다.
