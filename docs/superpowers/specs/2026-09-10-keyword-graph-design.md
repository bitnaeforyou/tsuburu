# 작품 키워드 설계

작성일: 2026-09-10
선행 스펙: `2026-09-09-artifact-import-design.md`

## 1. 남겨뒀던 파일

공개된 아티팩트의 `graph.csv`(198 MB)를 "보류"로 적어두고 쓰지 않았다.
한 줄이 낱말 하나다.

```
article_id,rank,keyword,score,tf,df,total_pages,dialogue_count,char_count
8035,1,에미,20.360738,7,292,157,1702,8542
```

작품마다 인식된 대사에 TF-IDF를 돌려 상위 100개를 뽑아둔 것이다. 임베딩
인덱스가 2.6 GB인데 이건 수십 MB이고, 임베딩이 답하던 질문 두 개를 그대로
답한다. **이 작품은 무엇에 관한 것인가**, 그리고 **비슷한 이야기는 무엇인가**.

## 2. 저장

`keywords.redb`:

| 테이블 | 내용 |
|---|---|
| `works` | id → LZ4로 접은 (낱말, 점수) 목록 |
| `words` | 낱말 → (순위 키, id) 멀티맵 |
| `meta` | 스키마 |

순위 키는 `u32::MAX - 점수×1000`이다. redb가 값을 오름차순으로 주므로,
이렇게 뒤집어 두면 **한 낱말의 게시 목록이 강한 작품부터** 나오고 질의가
일찍 멈출 수 있다.

작품당 100개를 다 두지 않고 **40개**만 남긴다. 꼬리는 한 페이지에서만 나온
잡음이다. 그리고 **20,000편을 넘는 낱말은 버린다** — 저장은 가장 많이
차지하면서 어느 작품에 대해서도 말해주는 게 없다. `df` 칸이 파일에 이미 있어
가져오는 중에 그대로 거를 수 있다.

## 3. 질의

- **무엇에 관한가**: `works`에서 한 번 읽는다.
- **낱말로 찾기**: 게시 목록을 앞에서부터 limit개.
- **비슷한 이야기**: 내 낱말마다 게시 목록을 훑으며 `내 점수 × 상대 점수`를
  더한다. 두 키워드 벡터의 희소 내적이다. 낱말 하나당 4,000개까지만 본다.

공유한 낱말을 무거운 순으로 함께 돌려준다. "왜 비슷한지"가 보이지 않으면
추천은 믿기 어렵다.

## 4. 재업로드

hitomi에는 같은 작품이 여러 ID로 올라와 있다. 재업로드본은 대사가 같으니
키워드도 같고 점수도 같아서, 이웃 목록이 한 작품의 사본으로 채워진다
(실측: `Intou Kaasan`이 같은 점수 868.1로 두 번 나왔다).

그래서 limit의 네 배까지 순위를 매긴 뒤, 상위 12개 낱말이 같은 것끼리
접는다. 같은 점수로 묶이면 **최근 ID**를 남긴다 — 대사 검색의 접기와 같은
규칙이다.

## 5. 같은 작품이 두 번 올 때

`graph.csv`에 한 id가 떨어진 두 자리에 나올 수 있고, 파일을 다시 가져올 수도
있다. 레코드는 덮어쓰면 그만이지만 **역색인은 두 벌이 남는다.** 그러면 그
작품이 이웃 점수에 두 번 들어가고, 공유 낱말 목록에 같은 낱말이 두 번 찍힌다
(실측으로 이렇게 드러났다: `공유: 낱말11 · 경찰 · 경찰 · 형사`).

그래서 쓰기 전에 이전 레코드를 읽어 그 게시 항목들을 먼저 지운다.

## 6. 실측

그 구현의 진짜 `graph.csv`(189 MB, 4,064,567행)로:

| | |
|---|---|
| 가져오기 | **16.8초** — 106,155편, 232만 낱말 (66만 행은 흔해서 버림) |
| `keywords.redb` | 258 MB |
| 무엇에 관한가 | 1 ms |
| 비슷한 이야기 | 8~15 ms |
| 낱말로 찾기 | 1 ms 미만 |

결과가 말이 되는지도 봤다.

- `8035` **비색의 각 상권** → 에미 · 에츠코 · 보스 · 비색 · 부인 · 변호사.
  이웃 1위는 **하권**(에츠코·부인·에미·보스를 공유).
- `4030599` **츄ー해줘 2** → 코헤이군 · 유키씨 · 관장 · 배설. 이웃 1위는
  **1편**(코헤이군·유키씨·항문·오줌을 공유).

2위 아래는 등장인물 이름 하나만 공유하는 작품이 섞인다. 그래서 공유 낱말을
같이 보여준다 — 왜 걸렸는지 보이면 독자가 판단할 수 있다.

## 7. 하지 않은 것

- **로컬 코퍼스에서 직접 TF-IDF 뽑기.** 한국어는 형태소 분석이 있어야
  낱말이 제대로 잘린다. 그 구현이 이미 해둔 일을 형태소 분석기 없이 다시 하면
  더 나쁜 결과가 나온다.
- 흔해서 버린 낱말과 아예 없는 낱말을 구분해 알려주기. 지금은 둘 다
  "그 낱말을 다루는 작품이 없습니다"로 나온다.
