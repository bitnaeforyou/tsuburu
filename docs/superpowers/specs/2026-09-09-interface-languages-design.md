# 인터페이스 언어 설계

작성일: 2026-09-09

## 1. 무엇이 문제였나

화면 문구가 전부 영어였다. 검색하는 사람도, 대사를 찾는 사람도 한국어권인데
버튼만 영어였다. 콘텐츠(제목·태그·대사)는 hitomi가 가진 언어 그대로 두어야
하지만, 그 둘레의 말은 읽는 사람의 언어여야 한다.

## 2. 형태

`web/src/lib/i18n.svelte.ts` 하나와 `locales/{en,ko,ja}.ts` 셋.

- **영어가 기준이다.** `en.ts`만 `as const`로 두고 `Key = keyof typeof en`,
  `Messages = Record<Key, string>`로 잡는다. 다른 언어 파일은 `Messages`로
  주석을 달아서, 키가 빠지면 번역이 없는 채로 도는 대신 빌드가 깨진다.
  (`as const`를 값에까지 걸면 "번역문이 영어 원문과 같아야 한다"는 타입이
  되어버려 한 번 걸렸다.)
- **치환은 `{name}` 하나뿐이다.** 복수형 규칙이나 성/수 일치는 넣지 않았다.
  한국어와 일본어에는 필요 없고, 영어에서 필요한 곳은 두 키로 갈랐다
  (`downloads.work` / `downloads.works`).
- **고르는 순서**는 저장된 선택 → 브라우저 언어 목록 → 영어. 선택은
  `localStorage`에 남기고, 시크릿 창처럼 저장이 막힌 곳에서는 이번 세션만
  유지한다.
- `document.documentElement.lang`을 함께 바꾼다. 스크린 리더와 줄바꿈이 이걸
  본다.

## 3. 어디까지 번역하나

| | |
|---|---|
| 버튼·라벨·설명문·aria-label·placeholder | 번역 |
| 언어 이름과 작품 종류(동인지·망가…) | 번역 |
| 제목·태그·작가 이름·대사 | 원문 그대로 |
| 서버 오류의 진단 문구 | 영어 그대로, 위에 번역된 한 줄을 얹는다 |

마지막 줄이 타협이다. 서버가 내는 문구까지 번역하려면 오류마다 코드와 인자를
주고받아야 하는데, 지금은 `ErrorKind` 다섯 가지에 대해 "무엇을 해야 하는지"를
번역해 앞에 놓고, 원문은 그 아래 작은 글씨로 남긴다.

## 4. 값

번들이 90.5 kB에서 120.0 kB로(gzip 32.4 → 42.4 kB) 늘었다. 세 언어를 모두
담아서다. 필요할 때만 받아오게 나눌 수 있지만, localhost에서 도는 프로그램에
쪼갤 값어치는 없다고 봤다.

## 5. 하지 않은 것

- 서버가 내는 오류 문구의 번역. 3절 참조.
- 언어별 날짜·숫자 서식. `toLocaleString()`이 브라우저 로케일을 따르므로
  인터페이스 언어와 어긋날 수 있다.
- 리더 화면의 언어 전환. 전환기는 내비게이션에만 있다.
