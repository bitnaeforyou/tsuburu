# tsuburu

**hitomi.la를 검색하고 읽는 가벼운 데스크톱 클라이언트.**

3.9 MB 파일 하나. Docker도, 따로 깔 런타임도, 처음에 받을 색인도 없습니다.

[English](README.md) · [릴리스](../../releases/latest) · MIT

</div>

```console
$ tsuburu
tsuburu is running at http://127.0.0.1:8420/
press ctrl+c to stop
```

- hitomi가 **이미 서빙 중인 색인을 검색** — 만들 것도 맞출 것도 없습니다
- 원본 해상도로 **읽고**, 작품이나 한 쪽만 **받아두고** 오프라인으로
- **기억나는 대사 한 줄로 작품 찾기** — 열어본 페이지가 내려오는 김에 인식됩니다
- **작가 팔로우**, 즐겨찾기, 멈춘 자리에서 이어 읽기
- 코퍼스를 넣으면 **146만 편 오프라인 검색**, **무엇에 관한 작품인가**,
  **비슷한 말로 찾기**까지
- 화면 언어 **한국어 / English / 日本語**

## 설치

설치되는 것은 없습니다. 받아서 열고 실행하면 끝입니다. 압축 안에 프로그램과
`START-HERE.txt`(한국어·영어)가 같이 들어 있습니다.

| 쓰는 컴퓨터 | [최신 릴리스](../../releases/latest)에서 받을 것 | 그다음 |
| :-- | :-- | :-- |
| Windows | `…windows-msvc.zip` | **tsuburu.exe** 더블클릭 |
| Mac, M1 이상 | `…aarch64-apple-darwin.zip` | **Start tsuburu.command** 더블클릭 |
| Mac, 인텔 | `…x86_64-apple-darwin.zip` | **Start tsuburu.command** 더블클릭 |
| Linux | `…linux-gnu.tar.gz` | **start.sh** 실행 |

서명이 없는 빌드라 각 운영체제가 **처음 한 번만** 경고합니다.

- **Windows** — 파란 *Windows의 PC 보호* 창이 뜹니다. *추가 정보* → *실행*.
- **macOS** — *개발자를 확인할 수 없어 열 수 없습니다*. **Start
  tsuburu.command**를 마우스 오른쪽 버튼으로 클릭하고 *열기*를 고르세요. 이
  실행기가 브라우저가 붙인 격리 표시까지 지우므로, 해야 할 일은 이것뿐입니다.
- **Linux** — 경고가 없습니다. 파일 관리자가 `start.sh`를 실행하지 못하면
  그 폴더에서 터미널을 열고 `./start.sh`를 입력하세요.

브라우저가 `http://127.0.0.1:8420/`로 열립니다. 성인임을 한 번 확인하면 검색
화면이 나옵니다.

### 받자마자 되는 것

방금 실행한 파일 하나 말고는 필요한 게 없습니다.

| | 되는 일 |
| :-- | :-- |
| **검색** | hitomi 태그를 한국어로도 영어로도. `-낱말`로 제외 |
| **읽기** | 원본 해상도, 보기 방식 셋, 양쪽 방향, 멈춘 자리에서 이어서 |
| **보관** | 작품이나 한 쪽만. hitomi가 안 되어도 열립니다 |
| **기억** | 즐겨찾기와 읽은 기록. 이 컴퓨터에만, 옮길 수 있는 파일로 |
| **대사 검색** | 열어본 작품 전부에 대해 — [아래](#대사-검색) 참고 |

### 따로 구해 오는 것

파일 세 개가 있으면 훨씬 많은 것이 됩니다. 크고, tsuburu와 함께 배포되지
않으며, 없어도 위의 것들은 그대로 됩니다. 이런 코퍼스는 이 사이트를 대상으로
만들어 배포하는 사람들이 있고, tsuburu는 그것을 읽을 뿐입니다.

| 하고 싶은 것 | 필요한 것 | 크기 | 가져오기 |
| :-- | :-- | --: | :-- |
| 직접 읽지 않은 작품까지 대사로 검색 | 인식된 텍스트(`llm-search-index`) | 3.9 GB | `tsuburu import-artifact <디렉터리>` |
| 제목·작가·캐릭터를 오프라인에서 | 메타데이터(`data.db`) | 2.2 GB | `tsuburu import-meta <파일>` |
| 무엇에 관한 작품인가, 비슷한 이야기 | 키워드(`graph.csv`) | 190 MB | `tsuburu import-keywords <파일>` |

가져오기 전에 서버를 끕니다 — 데이터베이스는 한 번에 한 프로세스만 엽니다.
코퍼스 디렉터리는 있는 자리에서 읽고 복사하지 않으므로, 외장 디스크를 포함해
어디에 두어도 됩니다.

**의미로 찾기**는 하나가 더 필요합니다. 그 색인을 만든 임베딩 모델인데, 수
기가바이트짜리 별도 내려받기이고 각자의 로컬 서버로 돌립니다. 설정하기 전까지는
화면에 나타나지도 않습니다.

### 어디에 쌓이나

| 플랫폼 | 경로 |
| :-- | :-- |
| macOS | `~/Library/Application Support/la.tsuburu.tsuburu/` |
| Linux | `~/.local/share/tsuburu/` |
| Windows | `%APPDATA%\tsuburu\tsuburu\data\` |

지우면 전부 초기화됩니다. 잃는 것은 가져온 것과 읽은 것뿐입니다.

## 검색

검색창 하나가 세 곳에 동시에 던집니다 — hitomi 태그, 로컬 제목, 인식된 대사 —
그리고 도착하는 구획부터 채웁니다.

한 줄로 섞지 않습니다. 태그 교집합과 대사의 퍼지 유사도는 같은 자로 잴 수 없고,
한 목록으로 만들면 순서가 임의로 정해집니다. 각 구획에는 그것만 보는 링크가
있습니다.

낱말은 AND로 묶이고 `-낱말`은 제외합니다. 번호나 번호가 든 hitomi 주소는 찾지
않고 바로 엽니다. hitomi의 색인은 낱말을 작품에 잇는 것이라 품번은 검색어가
아니라 주소이기 때문입니다.

이게 생각보다 중요합니다. hitomi는 작품을 **목록에서 먼저 빼고 한참 뒤에야**
파일을 지웁니다. 색인에서 사라진 작품 60편을 표본으로 확인해보니 **52편이 여전히
모든 쪽을 그대로 내려줬습니다.** hitomi 자체 검색에도 목록에도 없지만 스냅샷은
아직 알고 있으니, 로컬 검색으로 찾히고 품번으로 열립니다. 그런 작품에는
**hitomi 목록에 없음**이라고 붙습니다. 지금은 쪽이 남아 있고, 받아둘 수 있는
시간은 지금뿐이라는 뜻입니다.

터미널에서도 됩니다.

```console
tsuburu search "glasses -school"   # 검색
tsuburu gallery 4170351            # 작품 하나 살펴보기
tsuburu serve --port 9000          # 포트 지정 (0이면 빈 포트)
tsuburu serve --no-open            # 브라우저를 열지 않음
```

## 뷰어

작품은 먼저 자기 화면으로 열립니다 — 표지, 제목, 작가, 시리즈, 쪽 수, 태그,
모든 쪽의 썸네일, 같은 것에 관한 다른 작품. 읽기는 거기서 내딛는 한 걸음입니다. **읽기**, 전에 왔던 곳이면
**12쪽부터 이어 보기**. 뷰어를 닫으면 작품 밖이 아니라 이 화면으로 돌아옵니다.
대사 검색으로 찾은 줄만 예외로, 그 줄이 있는 쪽으로 바로 갑니다.

작품을 펼치는 방식이 셋이고, 고른 것은 다음에도 그대로 남습니다.

| 방식 | |
| :-- | :-- |
| **세로** | 모든 쪽을 한 줄로, 웹툰을 보듯이 |
| **한 장** | 한 번에 한 쪽 |
| **두 장** | 두 쪽을 나란히, 표지는 한 장으로 |

만화는 오른쪽에서 왼쪽으로 그려지므로 **우 → 좌**를 고르면 방향키도, 다음으로
넘어가는 화면의 쪽도, 두 장이 놓이는 순서도 함께 뒤집힙니다. 크기는 세로로 볼
때와 넘겨 볼 때를 따로 기억합니다. 한 줄로 볼 때는 너비를 채우는 편이, 넘겨 볼
때는 한 쪽이 화면에 다 들어오는 편이 낫기 때문입니다.

| | |
| :-- | :-- |
| **←** **→** | 읽는 방향대로 넘김 |
| **Space**, **PageDown** | 다음으로 |
| **F** | 전체 화면 |
| **Esc** | 뒤로 |
| 화면 왼쪽·오른쪽 1/3 누르기 | 넘김 |
| 화면 가운데 누르기 | 쪽 말고 나머지를 다 치웁니다. 다시 누르면 돌아옵니다 |
| 밀기 | 넘김 |
| 두 손가락, 두 번 누르기, **Ctrl** + 휠 | 확대. 끌어서 움직이고, 쪽을 넘기면 풀립니다 |
| 화면보다 긴 쪽을 끌기 | 손가락을 따라 움직입니다 |

슬라이더로 원하는 쪽에 바로 가고, **▦** — 나머지를 다 치웠을 때는 구석의 쪽
번호 — 를 누르면 모든 쪽이 썸네일로 한 번에 펼쳐집니다. hitomi가 가진 작은
사본이라 쪽 하나의 30분의 1이고, 화면에 보이는 것만 받아옵니다. 1,537쪽짜리
작품의 벽을 펼치는 데 140 KB쯤 듭니다.

다음 세 쪽은 도착하기 전에 미리 디코드해 두므로 넘기는 순간이 기다림이 아니라
한 프레임입니다. 한 장씩 넘길 때는 창에 쪽 하나만 올려 둡니다 — 1,537쪽짜리
작품이 이미지 1,537개가 아니라 1개입니다.

### 휴대폰에서

다섯 갈래는 엄지가 닿는 아래쪽에 붙고, 필터는 한 줄을 지키며 옆으로 밀리고,
누르는 것들은 클릭이 아니라 누르기에 맞는 크기가 됩니다. 뷰어는 모든 터치를
직접 받습니다 — 한 손가락은 넘기고 밀고 긴 쪽을 움직이며, 두 손가락은 확대
합니다 — 그래서 어느 것도 뒤쪽 화면의 스크롤로 새지 않습니다. 도움말도 기기에
따라 달라집니다. 휴대폰에 **Esc** 이야기는 하지 않습니다.

## 최신으로 두기

받아서 쓰는 복사본은 자기가 어느 릴리즈에서 왔는지 압니다. 빌드한 워크플로가
알려주기 때문이고, 소스에는 누구의 이름도 적혀 있지 않습니다. 켤 때 한 번
새 버전이 있는지 묻고, 있으면 설정 탭이 알려줍니다. 한 번 누르면 이 컴퓨터용
빌드를 받아 지금 도는 자리에 넣습니다. 덮어쓰지 않고 헌 것을 옆으로 옮긴 뒤에
넣으며, 도는 프로그램을 지우지 못하는 플랫폼에서는 다음에 켤 때 치웁니다.
그러고 나면 tsuburu를 다시 시작하라고 말합니다.

누르기 전에는 아무것도 받지 않고 아무것도 바꾸지 않습니다. 직접 빌드한
복사본은 물어볼 곳이 없어서 아무것도 제안하지 않습니다.

## 다른 기기로 옮기기

즐겨찾기, 팔로우한 작가, 어디까지 읽었는지가 tsuburu가 당신에 대해 갖고 있는
전부입니다. 즐겨찾기나 기록 화면의 **내보내기**가 셋을 JSON 파일 하나에 담고,
**가져오기**가 화면이 쓰는 것과 같은 경로로 되돌립니다. 지금 있는 것을 지우지
않고 더합니다. 프로그램이 받아들이지 못하는 기록은 건너뛰고 세어서 알려주며,
나머지는 그대로 들어갑니다.

## 오프라인으로 읽기

리더에 **다운로드**와 **이 쪽 받기**가 있고, 다운로드 탭이 지금 있는 것과
진행률을 보여줍니다.

페이지는 hitomi가 이미 주는 해시로 저장합니다. 그래서 재업로드본이 같은 페이지를
써도 파일은 하나고, 작품을 지울 때 다른 작품이 쓰는 페이지는 남습니다. 받아둔
작품을 읽을 때는 네트워크를 아예 타지 않습니다. 이미지 프록시가 디스크를 먼저
보고, 작품 정보를 못 받아와도 디스크의 페이지 목록만으로 열립니다.

## 대사 검색

hitomi의 색인은 제목과 태그만 압니다. 기억나는 대사로 찾으려면 페이지를 읽어야
합니다 — 운영체제의 인식기를 돌리고 텍스트만 남깁니다. 이미지는 읽자마자
버립니다.

### 읽는 대로 쌓인다

**열어본 작품은 보는 대로 읽어둡니다.** 그 페이지들은 어차피 화면에 보여주려고
내려옵니다. 그래서 이미지 프록시가 들고 있던 바이트를 인식기에 그대로 넘깁니다.
추가로 받는 것이 없고, 실제로 읽은 작품이 그 안의 한 줄로 찾히게 됩니다.

이미 텍스트가 있는 페이지는 건너뛰므로 다시 읽어도 비용이 없습니다. 설정 탭이
이렇게 모인 것을 용량과 함께 보여주고, 하나든 전부든 지웁니다.

### 배경 스윕

다른 것이고 **기본 꺼짐**입니다. 열어본 적 없는 갤러리를 받기 때문입니다. 대사
탭에서 켜면 앱이 열려 있는 동안 인기 있는 한국어 갤러리부터 색인합니다. 좁히는
방법이 둘 있습니다.

- **읽은 기록 가져오기** — 브라우저 기록의 hitomi 주소나 번호를 붙여 넣으면 다른
  것보다 먼저 색인합니다.
- **골라 담기** — 태그·언어·종류로 좁혀 그것만 담습니다.

이 컴퓨터에서 읽은 구절도 팩이 설정돼 있으면 함께 임베딩해 가져온 인덱스와
나란히 훑습니다. 그래서 **내가 읽은 작품에도 닿습니다.**

### 비슷한 말로 찾기

설정 탭의 스위치 하나입니다. 켜면 2.3 GB를 한 번 받습니다 — 가중치는 그걸 훈련한
사람들에게서, 실행기는 그걸 만든 사람들에게서 — 그리고 이 컴퓨터에서 돌립니다.
켜기 전에는 아무것도 받지 않고, 켠 뒤에도 아무것도 이 컴퓨터를 떠나지 않습니다.
끄면 멈추고 받아둔 파일은 남아서, 다시 켤 때는 가중치를 읽는 시간만 듭니다.
다시 시작해도 알아서 켜집니다. 이미 켜달라고 하셨으니까요.

그러면 검색창의 대사 옆에 **비슷한 말로**가 생깁니다. 어렴풋이 기억나는 대로 —
낱말이 틀려도, 문장이 반만 기억나도 — 써 보면 진짜 그 줄을 찾아옵니다. 못 하는
것은 장면을 설명해서 찾는 일입니다. 색인에 든 것이 짧은 대사 줄이라, 설명은 그
설명과 같은 낱말을 쓴 줄 근처로 갈 뿐입니다.

| | |
| :-- | --: |
| 가중치 | Qwen3-Embedding-4B, Q4_K_M, Qwen 배포, Apache-2.0 |
| 실행 | llama.cpp가 이 컴퓨터용으로 내놓은 공식 빌드 |
| 받는 양 | 2.33 GB 한 번. 끊기면 이어받습니다 |
| 두는 곳 | 나머지와 같은 자리. 지우면 그만큼 비워집니다 |

직접 돌리는 편이 낫다면 — 다른 양자화든, 네트워크 너머의 GPU든 — *거의 쓸 일 없는
것들* 안에 주소 칸이 그대로 있고 옆에 **확인** 버튼이 있습니다. 다른 모델은
그럴듯한 벡터를 주고 결과만 쓸모없어지므로, 색인에 이미 있는 구절을 다시 임베딩해
비교합니다. 0.9 아래면 코퍼스가 나쁜 것처럼 두지 않고 모델이 다르다고 말합니다.
맞는 모델은 1.000이 나옵니다.

### 읽은 것 나누기

비싼 것은 텍스트인데 그건 작습니다. 그래서 옮길 수 있습니다. 설정 탭이 이
컴퓨터가 인식한 것을 `.tsd` 샤드로 내보내고 남의 것을 가져옵니다. 파일은 이름에
든 해시로 검증합니다.

가져온 코퍼스의 텍스트는 **절대 들어가지 않습니다** — 샤드는 이 기계가 읽은
것이고, 코퍼스는 받을 사람이 직접 구할 것입니다.

## 무엇에 관한 작품인가

키워드 그래프는 작품마다 관통하는 낱말을 대사에 TF-IDF를 돌려 뽑아둔 것입니다.
임베딩 인덱스가 2.6 GB인데 이건 수십 MB입니다.

작품 화면에 그 낱말들이 뜨고, 각각이 그 낱말이 관통하는 다른 작품으로
이어집니다. 리더 아래에는 **비슷한 이야기** 줄이 있고 두 작품이 무엇을
공유하는지 함께 보여줍니다. 임베딩보다 거칠지만 — 공유한 의미가 아니라 공유한
낱말입니다 — 두는 값이 거의 없고 모델 없이 답합니다.

어떤 시리즈의 2권에서 물으면 1권을 답합니다. 등장인물 이름 넷을 공유하기
때문입니다. 2만 편을 넘는 낱말은 가져올 때 버리고, 그런 낱말을 찾으면 "없다"가
아니라 그렇게 말해줍니다.

## 작가

작품의 작가 이름이 그 사람이 그린 것 전부로 이어집니다. 최신순, 언어별 개수와
함께 — 읽는 언어에 머무를 수 있게. **팔로우**는 즐겨찾기 옆에 이름을 남깁니다.
메타데이터 스냅샷이 필요합니다.

## 표시 언어

한국어, English, 日本語. 처음에는 브라우저를 따르고 고른 것을 기억합니다.
전환기는 내비게이션 끝과 리더 헤더에 있습니다.

번역하는 것은 둘레의 말뿐입니다 — 제목·태그·대사는 hitomi가 가진 언어 그대로
둡니다. 숫자는 고른 언어의 방식으로 끊습니다. 오류는 영어 진단을 그대로 두되 그
위 한 줄, 무엇을 해야 하는지 말하는 부분은 번역합니다.

언어 추가는 `web/src/lib/locales/` 아래 파일 하나입니다. 영어 파일에 타입으로
묶여 있어서 빠진 문구가 있으면 빌드가 깨집니다.

## 플랫폼

검색·읽기·즐겨찾기·기록·다운로드·가져오기는 어디서나 됩니다. 텍스트 인식만
다릅니다. tsuburu는 모델을 담지 않고 그 기계가 이미 닿을 수 있는 것을 부릅니다.

| 플랫폼 | 인식 | 디코딩 |
| :-- | :-- | :-- |
| macOS | Vision | ImageIO |
| Windows | Windows.Media.Ocr | WIC — AVIF는 무료 AV1 Video Extension 필요 |
| 리눅스, 그 밖의 유닉스 | `tesseract` | `ffmpeg`, ImageMagick, `avifdec` 중 하나 |

앞의 둘은 운영체제에 들어 있습니다. hitomi가 AVIF로 주는데 leptonica가 그걸 못
읽어서 tesseract 앞에 디코더가 하나 필요합니다. 둘 중 하나가 없으면 설정 탭이
무엇을 깔아야 하는지 말합니다.

인식 품질은 같지 않습니다. 같은 한국어 페이지에서 Vision이 읽은 낱말 8개 중
tesseract는 7개를 찾았습니다. 매칭에는 충분하지만 — 한글 사이 공백을 무시하고
퍼지로 점수를 매기므로 — 줄 단위로는 더 지저분합니다.

### 문자 체계를 가리지 않는 매칭

제목과 대사는 한글·라틴·그 밖의 문자를 모두 덮는 하나의 인코딩으로 맞춥니다.
그래서 일본어 제목이나 키릴 문자 대사도 한국어와 같은 방식으로 걸립니다. 한글
사이 공백은 무시하고 라틴 낱말 사이 공백은 지킵니다. 작품은 그 작품의 언어로
읽습니다.

## 빌드

Rust 1.90+, Node 20+.

```console
cd web && npm install && npm run build && cd ..
cargo build --release
```

프론트엔드는 컴파일 시점에 바이너리 안으로 들어가므로 릴리스는 파일 하나입니다.
`web/dist`는 커밋하지 않습니다. 그 단계를 건너뛰고 빌드해도 컴파일은 되고, 빈
화면 대신 자산이 없다고 말합니다.

```console
cargo test --workspace                     # 오프라인, 기록해둔 바이트로
cargo test -p tsuburu-fetch -- --ignored   # 실제 사이트에 붙습니다
```

오프라인 스위트는 실제로 받아둔 바이트를 파싱하므로 이상화된 포맷이 아니라 진짜
포맷을 검증합니다. 사이트가 바뀌었는지는 라이브 스위트가 알려줍니다.

## 깨질 때

깨집니다. hitomi의 색인 포맷은 문서가 없고 도메인은 이미 한 번 옮겼습니다.
tsuburu는 읽은 것을 검사해서, 기대한 포맷이 아니면 **사이트가 바뀌었고
업데이트가 필요하다**고 말합니다. 틀린 결과나 빈 화면을 보여주지 않습니다.

hitomi 포맷에 대한 지식은 전부 `tsuburu-hitomi`에 있습니다. 고칠 곳은 거기
하나입니다.

## 알아둘 것

tsuburu는 전부 이 컴퓨터에서 돕니다. 콘텐츠를 호스팅하거나 재배포하지 않습니다.
보낸 요청만 중계하고 동시에 보내는 수를 제한합니다. 검색하는 사이트에는 성인용
자료가 있고 이 프로그램은 성인용입니다.

Ctrl-C나 TERM으로 끄면 데이터베이스가 깨끗이 닫힙니다. 강제로 죽이면 다음 실행
때 복구가 도는데, 코퍼스가 다 있으면 30초짜리 일입니다.
